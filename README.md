# 视频 Cut 关键帧截取工具（本地网页版）

把一段视频里**镜头切换（cut）的位置自动找出来**，把每个新镜头的第一帧截成图片，
作为参考图 / 分镜素材使用。

- 全部处理在**本机**完成，视频复制到本机工作目录，不上传云端
- 无需安装 ffmpeg（使用 OpenCV 内置解码）
- 操作：上传视频 → 自动分析 → 预览所有关键帧 → 一键打包 zip 下载（JPEG 原分辨率）

## 快速开始

1. 双击 `setup.bat`（首次安装环境，只需一次）
2. 双击 `启动工具.bat`，浏览器自动打开 `http://127.0.0.1:8765`
3. 拖入视频，等待分析完成，调整灵敏度后点「下载所选关键帧 (zip)」

> 命令行启动：`.venv\Scripts\python.exe server.py`（端口可用环境变量 `PORT` 修改）

## 页面布局

- **左栏：素材与工具**，依次是本地工作区、选择视频、检测参数、视频预览与手动选帧。
  视频载入后，工作区自动收起，上传区缩成一行，可随时展开。
- **右栏：关键帧结果**。分析进度显示在右栏顶部，也就是结果将出现的位置。结果工具栏（全选、拼图、下载）固定在顶部。
  两栏各自滚动：在左栏“逐帧微调”时，右栏的结果留在原位。
- **最左侧：功能导航**。按“开始、分析、修正、输出、管理”分组，显示实时状态（例如“45 张 · 选中 40”“分析中 63%”）。
  暂时不能用的项目变灰并说明原因。点击后跳到对应区域并短暂高亮；下载、拼图、空间管理直接执行。
  点顶部 ☰ 可收起为图标栏，收起或展开的状态会被记住。
- 窗口宽度小于 1100 像素时，自动变为单栏，导航改为左下角「☰ 功能」按钮打开的抽屉菜单。

## 检测原理

- **逐帧扫描**：顺序解码，缩到最长边不超过 160px 的彩色图，计算相邻帧平均绝对差（MAD）。
  不再跳过中间帧，也不丢弃颜色信息；仅保留最近两张小图，缓存每帧时间戳和差异分数。
- **筛选与截图**：检测突变，抑制“突变一帧后立即恢复”的闪光，按最小镜头间隔合并相邻峰值。
  截图按零基帧编号定位，不增加时间偏移。完成首次扫描后，改参数复用分数，仅重新筛选和截图。
- **灵敏度**：把差值阈值从「8×画面基准差（保守）」线性调到「2×（敏感）」，默认适中

- **截取哪一帧**：默认截切换后的第一帧（时间最准）。也可选「切换后约 0.5 秒」避开转场残影和压缩块，
  或「镜头开头最清晰的一帧」：在镜头前 1.5 秒内逐帧计算拉普拉斯方差，取明显最清晰的一帧。两种方式都不会越过下一个镜头，
  只作用于自动检测的镜头；手动补帧和微调保持用户选定的帧。结果中仍记录检测到的切换帧，跳过状态和微调按它对应，
  换截取方式重新分析后不会错位。

检测目标是硬切镜头。剧烈运动、渐变转场等仍可能误检或漏检。
时间码优先使用解码时间戳；后端不提供有效时间戳时按帧率估算，并在结果区提示。

## 参数说明

页面上默认只显示两项：「截到的镜头数量」（少 / 适中 / 多）和「每个镜头截取哪一帧」。其余在「高级参数」里。

| 参数 | 说明 |
| --- | --- |
| 镜头数量 | 少=灵敏度 25，适中=50，多=80；也可在高级参数里拖动灵敏度滑块 |
| 截取哪一帧 | 切换后第一帧 / 切换后约 0.5 秒 / 镜头开头最清晰的一帧 |
| 灵敏度 | 左=保守（帧少）；右=敏感（帧多，但大动作也可能被误判） |
| 保留首尾帧 | 额外在结果里加入视频第一帧和最后一帧 |
| 最小镜头间隔 | 默认 0.1 秒，可设 0～10 秒；密集剪辑可减小，0 表示不限制间隔 |
| 抑制单帧闪光 | 默认开启；真正的一帧镜头也可能被抑制，需要时关闭并减小最小间隔 |

下载后的 zip 内含：`001_00-00-03.200.jpg` 这类按序号+时间命名的图片，以及
`cuts.txt`（文件名、时间码、类型、零基帧编号对照表）。单次最多 500 张，按视频时间顺序导出。
ZIP 在磁盘生成，由浏览器原生下载，不在网页内构造整个文件的 Blob；是否保存成功请查看浏览器下载列表。

**画质说明**：zip 内为视频**原始分辨率**的 JPEG（质量 95，属于有损重编码）；页面网格里的
小图只是压缩预览，横竖屏均完整显示。单击缩略图可查看大图并单张下载。

## 结果保护与恢复

- 上传损坏文件不会删除已有视频或截图；不同上传会话相互独立。
- 重新分析期间旧结果仍可预览和下载；读取或写图失败会报告错误，不发布缺图或错位的结果。
- 快速改参数会取消旧任务，同一视频的工作线程串行处理；分析过程中也可以点击「取消分析」。
- 同一标签页刷新会恢复视频信息、检测参数和手动跳过的帧；同一视频重新分析也按帧编号保留跳过状态。
- 连接暂时中断会自动重试，连续失败后可点击「重试连接」。服务重启后，可从网页上方「本地工作区」恢复历史记录。
- `work/` 保存视频副本和当前结果。新记录默认只保留一套结果：微调只写入被修改的原图与预览图，其余图片沿用原文件，不复制整套。
- 新图片和索引保存成功后，自动清理不再被任何结果引用的旧图。正在下载的文件会延迟到发送结束后清理；删除失败会保留清理记录，稍后重试。
- 重新分析期间仍保留当前结果；成功后切换为新结果并清理旧图，失败则继续使用旧结果。更新后的旧页面、旧下载选择或拼图草稿需要重新载入，不会用旧时间码配新画面。
- 已存在的历史版本不会被升级静默删除，仍可在「空间管理与清理」中核对后选择移入回收区或永久删除。ZIP 响应结束后会清理临时压缩包。

图片可能分布在不同的内部文件夹中，但当前索引只指向一套有效素材。不要按文件夹名猜测版本并手动删除：未修改的图片会继续引用原文件。
保存操作有中断恢复记录，重启后只清理明确属于未提交操作的图片或已退役图片，不扫描删除未知用户文件。

## 视频预览、手动补帧与微调

分析完成后，结果上方会出现「视频预览与手动选帧」。

1. **定位画面**：播放或拖动左侧视频并暂停，右侧会显示对应的精确帧；也可输入秒数点击「定位画面」，或拖动「逐帧时间轴」。
2. **手动补帧**：用「前一帧／后一帧」确定右侧画面，点击「补入结果」。新截图标为「手动补帧」，按视频时间插入结果。
3. **微调已有截图**：点击对应卡片的「逐帧微调」，前后移动到满意的画面，再点「保存微调」替换该条目。点「退出微调」不保存本次定位。
4. **下载**：继续使用原有勾选和 ZIP 下载。时间码、帧号与图片按保存后的结果导出，重复帧不会再次添加。

以右侧精确图片和帧号为准，浏览器视频播放器的跳转不作为逐帧精度依据。
MP4 等浏览器支持的编码可直接播放；AVI 等不支持的格式会提示，仍可用秒数定位、逐帧时间轴和前后帧按钮操作。
界面帧号从 1 开始，`cuts.txt` 中的 `frame_index` 从 0 开始。

手动修改随结果保存到本地工作区：刷新页面、重新分析和重启服务后恢复记录均会保留。
分析期间不能编辑；保存失败或结果已被另一任务更新时不会覆盖旧结果。
每次微调只更新这一张图片；手动补帧只增加一张图片。不会再为每次微调创建一套完整的历史素材库。

## 从本地工作区恢复

误关浏览器后重新打开网页；误关命令行服务窗口后，先双击启动工具，再点击页面上方的「读取本地工作区」。
列表会显示 `work/` 中的记录，点击「恢复记录」即可继续查看、筛选、下载，无需重新上传视频。

- 新记录自动保存视频信息、完整截图索引、检测参数、手动修改、跳过选择及扫描缓存；恢复入口不会删除历史文件。
- 保存使用临时文件与原子替换。分析或编辑尚未完成时关闭工具，恢复的是最后一次完整保存的结果，未完成任务不会自动继续。
- 老版本只有图片而没有索引时，仍可恢复画廊与下载，但时间码和原帧号标为未知，不猜测它们。
- 有截图索引但缺少扫描缓存时，可直接下载；若要继续补帧或微调，点击「重新分析」重建缓存。
- 原视频、截图或索引缺失/损坏会明确提示，不会把不完整文件悄悄当作完整结果导出。
- 窗口关闭后已保存在磁盘的内容仍在；文件被手动删除后，恢复入口不能找回已删除的数据。

Windows 下浏览器刷新、取消请求引起的特定 `WinError 10054` 连接清理异常已作兼容处理，
会完成 socket 释放；其它应用错误仍正常记录，不全局屏蔽异常。

## 空间管理与清理

点击网页上方「空间管理与清理」，可查看工作区总占用、历史版本占用、回收区占用和磁盘剩余空间。
记录支持按名称搜索，以及按容量、时间、名称排序。展开记录后可查看视频副本、缓存、临时 ZIP、未知文件和各版本截图的明细。

1. 选择历史版本，或使用「保留最近 3 个版本／仅保留当前版本」生成候选。规则不会自动勾选当前版本、标记保留的版本或含手动修改的版本。
2. 点击「查看所选版本清理清单」，核对文件数量、容量、保留内容与后果。当前版本不能单独清理。
3. 默认「移入回收区」：可在原记录和回收文件未发生变化时恢复，**暂不释放磁盘空间**。原记录有后续修改时会保守拒绝覆盖恢复。
4. 选择「永久删除」才会实际释放所删文件占用，无法通过工具撤销。回收区永久删除、删除整条记录均需输入页面指定的确认文字。

高级清理支持临时 ZIP、扫描缓存、工作区视频副本和整条记录。缓存被清理后可重扫；视频副本被删除后只能查看和下载已有截图。
工作目录以外的原始视频和已下载文件不会删除。未知文件不当作临时垃圾；只有明确删除整条记录时才会随确认清单一起处理。
正在上传、分析、编辑、打包或下载使用的记录不能清理；准备好的下载包短时间内也受保护。清单有效期为 5 分钟，文件或记录变化后须重新预览。

回收内容及清理日志保存在 `work/.storage/`，不会混入正常恢复列表。操作中断后会在下一次访问时尝试回滚未完成的移动；
永久删除部分失败时，剩余文件留在回收区，页面显示失败项目，可重新预览后重试。回收区不会自动清空。
页面容量是文件大小统计，系统分配单元、回收记录和日志会影响最终磁盘可用空间。

## 制作参考拼图

在关键帧结果区点击「制作参考拼图」。首次打开会带入当前下载勾选，之后拼图面板的选图和排序独立，不改变原下载选择。
面板分三栏：左边选图、排序和写备注，中间是固定的排版预览，右边是可折叠的设置（排版、样式、标注）。

1. 勾选要用的图片，拖动排序，或使用「上移／下移」按钮。顺序为从左到右、从上到下。
2. 选择排版方式：
   - **智能排版**（默认）：按每张画面（含裁剪后）的比例自动分行，每行铺满宽度，不裁剪、不留白、没有空格。
     「整体形状」决定整张拼图偏横、偏竖还是接近正方形；「跟随画面比例」时 4 张、9 张同比例截图会排成 2×2、3×3。
   - **固定网格**：每格同样大小，可选格子比例；「裁剪铺满」居中裁剪，「完整显示」在格内留白。只排需要的行数。
3. 「每张最多」可选 4、9、12、16 张；超出时自动分成多张，用上下页按钮逐张预览。
4. 选择样式预设（浅灰卡片、白底细边、深色画廊、无缝紧凑），或单独调整间距、圆角、底色、阴影，可加标题。
   没有间距时不加圆角，避免拼缝处露出底色的小缺口。
5. 标注内容可选「拼图内序号」（跨页连续编号）、「原截图编号」、「时间码」；位置可选画面四个角或「图片下方」。
   视频自带字幕多在下方，默认放在右上角；放到图片下方则完全不遮挡画面。
6. **备注 / 分镜**：在顺序列表里，或在预览中单击选中一张后，给它写一行备注（最多 60 字），例如“航拍 / 推镜”。
   备注显示在图片下方，并写入分镜表。
7. 在预览中拖动画面到另一张上交换位置；双击画面（或点「裁剪」）打开裁剪窗口，
   可自由框选或按 16:9、4:3、1:1 等比例裁剪，滚轮缩放，只影响拼图、不修改原截图。
8. 点击「生成成品并查看」，在弹窗里确认后下载 PNG 或 JPEG（质量 95%）。合成读取原分辨率截图，不使用缩略图。

右上角两个按钮：
- **下载全部拼图 (zip)**：逐张生成所有页，连同 `分镜表.csv` 打包下载。
- **导出分镜表 CSV**：按拼图顺序列出原截图编号、时间码、帧编号、备注和裁剪范围，可用 Excel 直接打开（UTF-8 带 BOM）。

**拼图草稿随工作区保存**：选图顺序、裁剪和备注保存在该视频的工作目录里（`manifest.json`），按检测到的切换帧对应，
刷新、换浏览器、重启工具、重新分析同一视频后都能恢复；恢复工作区记录时也一并找回。修改后约 0.6 秒自动保存。
旧版只存在浏览器里的备注，第一次打开拼图面板时会自动移入工作区。
拼图设置（输出、排版、样式、标注）是个人偏好，记在本浏览器中，下次打开自动沿用；标题按视频填写，不会沿用。

「保留原图细节（不缩放）」模式按网格原尺寸无缝拼接，不缩放、不裁剪，也不加间距、圆角、标题、标注或备注，要求同批图片尺寸一致。
图片缺失或读取失败时不会导出不完整拼图。放大较小原图不会增加真实细节。

标题和标注使用中文字体：依次查找环境变量 `KEYFRAME_FONT`、工具（或 exe）旁边 `fonts/` 文件夹里的 .ttf/.otf/.ttc，
以及系统自带的微软雅黑、黑体、苹方、Noto Sans CJK、文泉驿等。都找不到时会在尺寸说明中提示。

排版由服务器计算一次，预览（Konva）和成品（Pillow）使用同一份坐标；智能排版的分行算法移植自 Flickr
justified-layout，裁剪使用 Cropper.js，均为 MIT 许可，见 `static/vendor/README.md`。
合成在本机完成，成品和打包文件是工作目录中的临时文件，按需清理，不上传云端。下载请在浏览器下载列表确认保存结果。
当前页面内关闭再打开同一结果的拼图面板，会保留草稿；刷新网页或切换结果版本后需重新选择图片。
生成拼图前、合成完成时和下载前都会核对当前结果；关键帧已更新时会提示刷新，防止沿用过期的拼图选择。

## 快速挑选结果

- **快捷键**（焦点不在输入框、且没有打开其它面板时生效；在结果区按 `?` 可展开说明）。单击任一卡片后，
  它会出现蓝框和「当前」标签，之后即可用方向键切换；开着中文输入法时也能用：

  | 按键 | 作用 |
  | --- | --- |
  | ← → ↑ ↓ | 移动当前卡片（蓝框），上下按实际列数跳一行 |
  | 空格 / X | 保留或跳过当前卡片 |
  | Enter | 查看原图；大图里 ← → 翻页、空格保留/跳过、Esc 关闭 |
  | E | 逐帧微调当前卡片 |
  | Shift + 单击 | 把上次单击到这次之间的卡片设为同样的保留 / 跳过 |

- **相似画面提示**：每张截图与前一张的缩略图比较（32×18 缩略颜色图的平均色差），相似度 ≥ 80% 的卡片标出
  “与上一张相似 xx%”，工具栏的「跳过相似画面 (N)」可一键跳过，每组保留第一张；单击卡片可随时恢复。
  没有相似画面时按钮显示「未发现相似画面」。
  只与前一张比较，因此 A→B→A 这类正常的来回剪辑不会被误标。

## 常见问题

- **有些切换没截到** → 把灵敏度调高（例如 70~90），工具会自动重新分析
- **截多了 / 画面相似** → 调低灵敏度；也可以在结果里单击某张图把它标为“跳过”，
  下载时会自动排除
- **截图有运动模糊或转场残影** → 「每个镜头截取哪一帧」改为「切换后约 0.5 秒」或「镜头开头最清晰的一帧」
- **提示“无法解析该视频”** → 编码不受支持（如个别 AV1/ProRes 封装），可先用
  格式工厂等转成 H.264 的 mp4 再试
- **大视频很慢** → 首次仍需顺序解码全部画面，速度取决于编码、分辨率和硬件；
  完成扫描后再调参数可复用缓存。数值缓存约每帧 16 字节（30 fps 一小时约 1.7 MB），不含解码器及图片等开销。

├─ static/collage*.js  拼图面板与 Konva 预览
├─ static/vendor/      Konva、Cropper.js（本地文件，无需联网）
├─ tests/              后端及页面状态回归测试
├─ requirements.txt    运行依赖（setup.bat 与 CI 共用）

## 开发备注

依赖：`numpy` `opencv-python-headless` `fastapi` `uvicorn` `python-multipart` `Pillow`
（Python 3.10+，均安装在项目内 `.venv`，不影响系统 Python）。

回归验证（后端使用标准库 unittest；前端测试另需 Node.js 18+，使用工具本身不需要 Node.js）：

```bat
.venv\Scripts\python.exe -B -m unittest discover -s tests -v
node --test "tests/*.test.cjs"
```

测试使用临时生成的视频和临时工作目录，不改动 `work/` 内已有数据。覆盖帧精度、颜色切换、短镜头、
闪光抑制、截取策略、内存图片数量、任务竞争、失败结果保护、导出、拼图排版与草稿、快捷键及页面状态恢复。

**自动测试（GitHub Actions）**：每次推送和合并请求都会在 Ubuntu 与 Windows 上运行全部测试；通过后在 Windows 上
实际打包免安装版，启动打包出的 exe 检查页面、脚本和接口可用，并把 `KeyframeTool-windows` 作为构建产物上传
（在 GitHub 仓库的 Actions 页面对应运行记录底部下载，保留 14 天）。

**代码格式**：Python 使用 ruff（`ruff format .`，行宽 120，保留原引号），网页脚本与样式使用 prettier
（`npx prettier --write "static/*.js" "static/*.css" "tests/*.cjs"`），配置见 `pyproject.toml` 与 `.prettierrc.json`；
`static/vendor/` 下的第三方文件不做改动。

## 打包成免安装 exe（可选）

给没有 Python 环境的人使用时，先运行过一次 `setup.bat`，再双击 `build_exe.bat`（等同于
`.venv\Scripts\python.exe build_exe.py`，首次会自动安装 PyInstaller，约需几分钟）。

产物是 `dist\KeyframeTool\` 文件夹（约 250 MB），把整个文件夹压缩后发给对方即可：
对方解压后双击其中的 `KeyframeTool.exe`，浏览器会自动打开。`work`（数据）和 `fonts`（可选字体）文件夹
都在 exe 旁边；文件夹内附 `使用说明.txt`。采用文件夹形式而非单文件 exe，是为了每次启动不必先解压整个运行环境，打开更快。
